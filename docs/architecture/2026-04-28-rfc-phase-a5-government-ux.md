# RFC — Phase A5: Government-grade UX baseline

**Status:** Draft (design only — not yet implemented)
**Author:** Project team (2026-04-28)
**Reviewer:** project owner
**Depends on:** none (greenfield design layer)
**Blocks:** future external accessibility audits, ministry handover, public sector reuse

---

## 1. Why this RFC exists

The audit at `docs/architecture/2026-04-28-design-system-review.md` benchmarked
the current applicant + officer UI against **gov.uk** (UK), **digital.gov**
(US), **bund.de** (Germany), and the Thai DGA's own evolving guidelines.
The gap that mattered most wasn't components — it was the absence of a
**governance layer**: persistent footer with ministry attribution, an
accessibility statement, language toggle, contact-of-record, and a
last-updated stamp. Government users expect those signals; their
absence makes a system feel like a startup demo.

This RFC scopes the smallest set of changes that close that gap without
rewriting the design system, and sets up an ESLint-enforced contract so
the gap doesn't reopen the next time someone copy-pastes a layout from
a fresh template.

## 2. Non-goals

- Not a Tailwind → CSS-Modules / shadcn migration
- Not a wholesale visual rebrand (typography, palette, iconography stay)
- Not a CMS-driven content system (footer copy stays in code for v1)
- Not WCAG 2.2 certification (we aim for AA-equivalence; certification
  is operator work after the code lands)

## 3. Current state — what exists today

- `apps/web-app/src/components/layout/Header.tsx` is canonical for both
  applicant and officer surfaces, includes ministry logo + bilingual
  switch
- No equivalent canonical `Footer.tsx`. Footer is rendered ad-hoc per
  page or omitted entirely
- `apps/web-app/src/app/(public)` has its own footer for the marketing
  pages — different markup, different copy
- Color tokens live in `tailwind.config.js` `theme.extend.colors.gov.*`
  but consumers reach for raw `#1d4ed8` instead about 60% of the time
  (counted in the audit)
- No `accessibility-statement` page exists. Headers have no
  `lang="th"` attribute on `<html>` for routes that are Thai-default

## 4. Proposed design

### 4.1 Layout contract

Introduce **one** authoritative layout primitive at
`apps/web-app/src/components/layout/GovLayout.tsx`. Every applicant
and officer page renders inside it. Marketing pages can opt out via
`<GovLayout chrome="minimal">` (header + footer only, no sidebar).

```tsx
<GovLayout>          // <html lang="th"> + skip-link + Header + main + Footer
  <PageHeader … />
  <main id="main-content">{children}</main>
</GovLayout>
```

Required slots:

| Slot | Source of truth | Notes |
|---|---|---|
| Ministry logo | `public/static/gov/logo-full.svg` | Single asset, served as PNG fallback |
| Ministry name | `shared/ministry-contact.js` | Already exists from P0-8 |
| Last updated | Build-time `process.env.NEXT_PUBLIC_BUILD_DATE` | Footer right corner |
| Lang toggle | URL param `?lang=en` | Persists in cookie `gacp-lang` |
| Skip-to-content link | Hardcoded in `GovLayout` | First focusable element |
| Accessibility statement link | `/accessibility` | New page, see §4.4 |
| Contact-of-record | `shared/ministry-contact.js` (phone, email) | Footer center |
| Sitemap link | `/sitemap.xml` | Generated by Next.js, exposed in footer |

### 4.2 Persistent footer (`Footer.tsx`)

```
┌─────────────────────────────────────────────────────────┐
│ [Ministry Logo]  สำนักงานคณะกรรมการอาหารและยา          │
│                  88/24 ถนนติวานนท์ นนทบุรี 11000      │
│                  โทร {ministry-contact.phone}           │
│                  {ministry-contact.email}               │
│                                                         │
│  About | Accessibility | Privacy | Terms | Sitemap     │
│                                                         │
│  Last updated 2026-04-28  ·  Version v3.4.0  ·  TH | EN│
└─────────────────────────────────────────────────────────┘
```

Three columns on desktop (logo + identity / quick links / version
stamp), single column on mobile. Min height 160 px so it visually
"closes" the page on short content. Background uses
`bg-gov-darknavy` token (already in palette).

### 4.3 Color + typography enforcement

Add an ESLint rule (custom, in `eslint-plugin-gacp/rules/no-raw-color.js`)
that fails if any `className` or inline style contains a 6-digit hex
NOT also present in `tailwind.config.js`'s `theme.extend.colors`. Output
explains: "use a token like `text-gov-blue-700` instead of `#1d4ed8`".
Allow-list: `#fff`, `#000`, `currentColor`, hexes in `*.test.tsx`.

Drives the 60% raw-hex rate to ~0% over time (advisory at first, gate
later — same ratchet pattern as the lint baseline added in PR #21).

### 4.4 Accessibility statement page

New route `/accessibility` rendered from
`apps/web-app/src/app/accessibility/page.tsx`. Content sourced from
`docs/legal/accessibility-statement-2026-04.md` (committed copy, no
CMS yet). Template fields: WCAG target level (AA), known issues
(empty initially — populated after first external audit), date of
last review, contact for accessibility complaints (uses
`shared/ministry-contact.js`).

### 4.5 Language attribute + lang toggle

`<html lang="th">` set in `apps/web-app/src/app/layout.tsx` based on
the cookie. Toggle in header swaps between `th` / `en` and persists.
Server-side rendering reads the cookie, so no flash on first paint.

### 4.6 Self-host Sarabun font

Currently fetched from Google Fonts at runtime. For a government
site this is both a privacy concern (third-party request leaks
referer to Google) and a reliability concern (CDN failure breaks
rendering). Vendor `Sarabun-{Regular,Medium,Bold,Italic}.woff2`
from Google's official OFL release into
`apps/web-app/public/static/fonts/`, swap `next/font/google` for
`next/font/local`. Net asset cost: ~200 KB, served from same origin.

footer fragments). 7 PRs of comparable size to the ones merged in
v3.4.0. **Steps 1 + 6 are already in flight as PR #24** — pure additive,
zero migration; the remaining 6 steps each migrate or extend.

## 6. Definition of done

- Every applicant and officer page renders inside `GovLayout`
  (verified by a `__tests__/integration/layout-coverage.test.tsx`
  that snapshots at least one page per top-level route prefix and
  asserts the footer is present)
- `/accessibility` resolves with 200 and contains the legal copy
- Lighthouse accessibility score ≥ 95 on `/health/dashboard`,
  `/provider/dashboard`, and `/`
- ESLint `no-raw-color` ratchet at 0 raw hexes in main (or
  documented exclusions for `*.test.tsx` only)
- Sarabun served from `/_next/static/media/sarabun-*.woff2`,
  no `fonts.googleapis.com` requests in DevTools network panel
- Footer's "last updated" matches the deployed git SHA's commit date

## 7. What this RFC does NOT decide

- Whether to adopt `shadcn/ui` going forward — separate proposal
- Whether to write our own Tailwind preset for ministry sites —
  premature; first internalize the contract above
- Mobile app design parity — out of scope; mobile uses Flutter and
  follows Material 3 by default

## 9. Concrete UX-clutter list captured 2026-04-28

User feedback during the session named **`/health/planting/<id>`** as
"งง / ซ้ำซ้อน / ดูวุ่นวาย". The Explore agent's audit on
`apps/web-app/src/app/health/planting/[id]/client-view.tsx` found
duplications that should be folded into Phase A5 step 9 (page-level
information-density review). Captured here so the work is concrete
when an engineer picks it up:

| Duplication | Lines | Recommendation |
|---|---|---|
| Cycle name shown 3 times (h2 title, subtitle, "Quick Tabs" bar) | ~143, 145, 272-293 | Title in `PageHeader` once. Drop the Quick Tabs bar — `Tabs.List` at 374-384 already provides navigation. |
| Status badge in header AND in the "process status" card | 139, 199-201 | Single badge in `PageHeader`. Reference it from the card by status colour, not by re-rendering the badge. |
| 5+ overlapping alerts (no-cert / legacy harvest / over-plan / integrity) | 196-247, 255-270 | Consolidate into one `<Disclosure>` "Status overview" with sub-items. Empty state hides the whole disclosure. |
| Tab bar appears twice (proper `Tabs.List` + decorative "Quick Tabs") | 272-293 + 374-384 | Delete `Quick Tabs` block; it duplicates `Tabs.List`. |

Same pattern likely exists on other `/health/(*)/[id]/client-view.tsx`
routes (the planting page is just where the user noticed first). When
GovLayout (§4.1) lands, every page-level layout flows through it, and
this kind of duplication becomes mechanically removable rather than
hand-audited per page. Net: this list is a **symptom** of the missing
layout primitive, not 4 independent bugs to fix one by one.

A separate "applicant detail page" issue surfaced in the same
feedback (`/health/applications/<id>` rendering wrong action card
when `status=REGISTERED + phase1Status=PAID`) was a **data drift bug**,
not a UX one. Fixed in v3.4.2 — see commit
`fix(applicant-ux): canonical phase status …`. Documented here only
to keep the audit-trail honest about what was UX vs. what was state
machine.
