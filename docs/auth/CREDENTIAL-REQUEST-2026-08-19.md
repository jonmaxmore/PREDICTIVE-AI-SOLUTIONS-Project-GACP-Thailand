## ฉบับที่ 1 — ถึง สำนักสุขภาพดิจิทัล กระทรวงสาธารณสุข (Health ID + Provider ID)

ที่ ⟨เลขที่หนังสือกรมฯ⟩
⟨ส่วนราชการเจ้าของหนังสือ: กรมการแพทย์แผนไทยและการแพทย์ทางเลือก ที่อยู่⟩

วันที่ ⟨วัน เดือน ปี⟩

**เรื่อง** ขอเชื่อมต่อระบบยืนยันตัวตน Health ID และ Provider ID สำหรับระบบรับรองมาตรฐาน GACP สมุนไพร

**เรียน** ผู้อำนวยการสำนักสุขภาพดิจิทัล กระทรวงสาธารณสุข

**สิ่งที่ส่งมาด้วย** รายละเอียดทางเทคนิคการเชื่อมต่อ (ภาคผนวก ก) จำนวน 1 ฉบับ

ด้วยกรมการแพทย์แผนไทยและการแพทย์ทางเลือกได้พัฒนา "ระบบรับรองมาตรฐาน GACP สมุนไพร" (โดเมน gacpth.com) เพื่อให้บริการรับคำขอ ตรวจประเมิน และออกใบรับรองมาตรฐานการปลูกและเก็บเกี่ยวสมุนไพรแก่เกษตรกรและวิสาหกิจชุมชนทั่วประเทศ โดยระบบดังกล่าวกำหนดให้การยืนยันตัวตนของผู้ใช้งานกระทำผ่านระบบยืนยันตัวตนกลางของหน่วยงานรัฐเป็นช่องทางหลัก ได้แก่ Health ID (สำหรับประชาชน/เกษตรกร) และ Provider ID (สำหรับเจ้าหน้าที่และบุคลากรผู้ตรวจประเมิน) ซึ่งอยู่ในความดูแลของสำนักสุขภาพดิจิทัล

ในการนี้ กรมฯ จึงขอความอนุเคราะห์จากสำนักสุขภาพดิจิทัล ดังนี้

๑. **ออก OAuth client credentials ของระบบ GACP** จำนวน ๒ ชุดแยกจากกันตามคู่มือการเชื่อมต่อ ได้แก่
  (ก) ชุด Health ID: `client_id` และ `client_secret`
  (ข) ชุดระบบ Provider ID: `client_id (PID)` และ `secret_key`
  ทั้งสภาพแวดล้อมทดสอบ (UAT) และใช้งานจริง (Production)

๒. **ลงทะเบียน redirect URI** ของระบบ GACP ดังนี้
  - `https://staging.gacpth.com/auth/callback/healthid` และ `https://gacpth.com/auth/callback/healthid`
  - `https://staging.gacpth.com/auth/callback/providerid` และ `https://gacpth.com/auth/callback/providerid`

๓. **ขอรับเอกสารทางเทคนิคเพิ่มเติม ๒ รายการ** ซึ่งจำเป็นต่อการพัฒนาให้แล้วเสร็จ (รายละเอียดในภาคผนวก ก)
  (ก) คู่มือ/ข้อกำหนดของ **profile endpoint ฝั่งประชาชน (Health ID)** — คู่มือฉบับที่กรมฯ ได้รับยังไม่ครอบคลุมส่วนนี้
  (ข) ข้อกำหนด**อัลกอริทึมของค่า `hash_cid`** ที่ระบบ Provider ID ส่งกลับใน profile — เพื่อให้กรมฯ สามารถจับคู่บัญชีเจ้าหน้าที่ได้อย่างถูกต้องและปลอดภัย

จึงเรียนมาเพื่อโปรดพิจารณาให้ความอนุเคราะห์ และขอขอบคุณมา ณ โอกาสนี้

ขอแสดงความนับถือ

⟨ลงชื่อผู้มีอำนาจลงนามของกรมฯ⟩

ผู้ประสานงานด้านเทคนิค: ⟨ชื่อ-ตำแหน่ง อีเมลราชการ โทรศัพท์⟩

### ภาคผนวก ก — รายละเอียดทางเทคนิค (แนบท้ายฉบับที่ 1)
1. ระบบ GACP เชื่อมต่อแบบ OAuth 2.0 authorization-code ตาม "คู่มือการเชื่อมต่อระบบ Provider ID ด้วย OAuth Health ID" โดยพัฒนาส่วนเชื่อมต่อฝั่ง Provider ID ไว้แล้วตามคู่มือ (การแลก Health ID token → Provider ID token → profile)
2. **คำถามที่ ๑ — Health ID ฝั่งประชาชน:** คู่มือฉบับที่ได้รับระบุ endpoint ฝั่งเจ้าหน้าที่ครบถ้วน แต่ยังไม่ปรากฏข้อกำหนดของ **profile endpoint สำหรับประชาชนทั่วไป** (เส้นทางที่เกษตรกรใช้ยืนยันตัวตน) — ขอทราบ URL, วิธีเรียก, และโครงสร้างข้อมูลที่ส่งกลับ หรือคู่มือฉบับที่ครอบคลุมส่วนนี้
3. **คำถามที่ ๒ — `hash_cid`:** profile ของ Provider ID ส่งค่า `hash_cid` กลับมา — ขอทราบอัลกอริทึมและพารามิเตอร์ที่ใช้ (เช่น ฟังก์ชันแฮช, salt/key, รูปแบบ input) เพื่อให้กรมฯ คำนวณเทียบฝั่งตนเองได้ โดยไม่ต้องส่งหรือจัดเก็บเลขบัตรประชาชนในรูปแบบเปิดเผย
4. มาตรการคุ้มครองข้อมูลฝั่ง GACP: ระบบไม่จัดเก็บเลขบัตรประชาชนแบบเปิดเผยในตารางเชื่อมบัญชี (ใช้ keyed HMAC แบบ domain-separated) และบันทึกการใช้งาน (audit log) ไม่มีข้อมูลส่วนบุคคลแบบเปิดเผย

## ฉบับที่ 2 — ถึง กรมการปกครอง (สำนักบริหารการทะเบียน) — ThaID

ที่ ⟨เลขที่หนังสือกรมฯ⟩

วันที่ ⟨วัน เดือน ปี⟩

**เรื่อง** ขอลงทะเบียนใช้งานระบบพิสูจน์และยืนยันตัวตนทางดิจิทัล (ThaID) ระดับใช้งานจริง สำหรับระบบรับรองมาตรฐาน GACP สมุนไพร

**เรียน** อธิบดีกรมการปกครอง (ผ่านสำนักบริหารการทะเบียน)

**สิ่งที่ส่งมาด้วย** รายละเอียดทางเทคนิคการเชื่อมต่อ (ภาคผนวก ข) จำนวน 1 ฉบับ

ด้วยกรมการแพทย์แผนไทยและการแพทย์ทางเลือกได้พัฒนา "ระบบรับรองมาตรฐาน GACP สมุนไพร" (โดเมน gacpth.com) ซึ่งกำหนดให้ประชาชนผู้ยื่นคำขอยืนยันตัวตนผ่านระบบ ThaID เป็นช่องทางหลัก ขณะนี้กรมฯ ได้พัฒนาและทดสอบส่วนเชื่อมต่อตามคู่มือสำหรับผู้ให้บริการ (ฉบับ Sandbox และ Production) แล้วเสร็จ และได้ตรวจสอบความสอดคล้องกับคู่มือครบถ้วนแล้ว

ในการนี้ กรมฯ จึงขอความอนุเคราะห์ ดังนี้

๑. **ลงทะเบียนกรมฯ เป็นผู้ให้บริการ (Relying Party)** ในระบบ ThaID ระดับใช้งานจริง และออก `client_id` / `client_secret` ของระบบ GACP

๒. **ลงทะเบียน redirect URI**: `https://staging.gacpth.com/auth/callback/thaid` และ `https://gacpth.com/auth/callback/thaid`

๓. **ขอบเขตข้อมูล (scope)** ที่ประสงค์ใช้: `openid pid given_name family_name` (เลขประจำตัวประชาชนและชื่อ-สกุล เพื่อการจับคู่บัญชีผู้ยื่นคำขอเท่านั้น)

๔. ขอทราบ**ขั้นตอนและเอกสารประกอบการอนุมัติ**เพิ่มเติม หากมีนอกเหนือจากการลงทะเบียนผ่าน https://digitalid.bora.dopa.go.th

จึงเรียนมาเพื่อโปรดพิจารณาให้ความอนุเคราะห์ และขอขอบคุณมา ณ โอกาสนี้

ขอแสดงความนับถือ

⟨ลงชื่อผู้มีอำนาจลงนามของกรมฯ⟩

ผู้ประสานงานด้านเทคนิค: ⟨ชื่อ-ตำแหน่ง อีเมลราชการ โทรศัพท์⟩

### ภาคผนวก ข — รายละเอียดทางเทคนิค (แนบท้ายฉบับที่ 2) — คำถามประกอบ (ไม่เป็นเงื่อนไขการอนุมัติ)
1. กรมฯ พัฒนาส่วนเชื่อมต่อตามคู่มือ §6.1–6.2 (authorization-code + HTTP Basic ที่ token endpoint) และทดสอบกับสภาพแวดล้อม Sandbox (imauthsbx.bora.dopa.go.th) ด้วย credential ทดสอบตามคู่มือ
2. **คำถามที่ ๑:** ค่า `sub` ใน id_token ระดับ Production เป็นเลขประจำตัวประชาชนโดยตรงหรือเป็นรหัสอ้างอิงเฉพาะระบบ (คู่มือแสดงตัวอย่างจาก introspect เท่านั้น) — กรมฯ ออกแบบให้รองรับทั้งสองกรณีแล้ว แต่ขอทราบเพื่อยืนยันการออกแบบการคุ้มครองข้อมูล
3. **คำถามที่ ๒:** ระบบ ThaID มีหรือมีแผนรองรับพารามิเตอร์ความมั่นคงเพิ่มเติมหรือไม่ ได้แก่ PKCE (`code_challenge`), `nonce`, หรือการระบุระดับความเชื่อมั่น (`acr`/`amr`) — คู่มือฉบับปัจจุบันไม่ได้ระบุ กรมฯ จึงยังไม่ได้เปิดใช้ หากมีข้อกำหนด กรมฯ พร้อมปรับตาม
4. **คำถามที่ ๓:** ค่า `api_key` ที่ปรากฏในชุด credential (คู่มือ Sandbox §9) จำเป็นต้องส่งประกอบคำขอใดหรือไม่ — ตัวอย่างใน §6.1–6.3 ไม่ได้ใช้งานค่าดังกล่าว
