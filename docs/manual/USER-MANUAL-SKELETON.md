## 2. จ่ายเงิน — รอบที่ 1 (ค่าตรวจเอกสาร)

**ที่อยู่หน้าเว็บ**: `/health/payments`

**ควรเห็นอะไร**
- รายการใบแจ้งหนี้ (invoice) ที่ต้องจ่าย พร้อมยอดเงิน
- ปุ่ม/หน้าต่างอัปโหลดสลิปโอนเงิน (ใช้งานได้เสมอ — เป็นช่องทางหลักวันนี้)

**กดอะไร**
- กด "แนบสลิป" → เลือกภาพสลิปโอนเงิน → ส่งให้เจ้าหน้าที่การเงินตรวจ (สถานะรอตรวจสลิป)
- เมื่อเจ้าหน้าที่อนุมัติสลิปแล้ว สถานะจะเปลี่ยนเป็น `DOC_FEE_PAID` โดยอัตโนมัติ

**จุดที่ยังไม่เปิด**
- **ช่องทางจ่ายเงินออนไลน์ผ่านบัตร/พร้อมเพย์ (Stripe) ยังไม่เปิดใช้งานจริง** วันนี้เห็น**เฉพาะ**ปุ่ม
  อัปโหลดสลิปธนาคารเท่านั้น (ต้องเปิด flag ทั้งฝั่งเว็บและฝั่งระบบหลังบ้านพร้อมกันก่อน ยังไม่เปิด)
  แม้เปิด flag แล้ว หน้าชำระเงินก็ยังค้างที่ "รอชำระเงิน" ไม่มี QR ให้สแกนจริง — **ห้ามสาธิตว่าใช้จ่ายเงิน
  ออนไลน์ได้แล้ว**
- เลขบัญชีธนาคารปลายทางที่แสดงบนสลิป: ยังรอฝ่ายการเงินยืนยัน (ไม่ได้ยืนยันจากไฟล์จริงในรอบตรวจนี้ —
  ต้องตรวจซ้ำก่อนประกาศว่าครบ)

**เจ้าหน้าที่เห็นอะไร / กดอะไร**

## 6. นัดตรวจ ⚠️

**ที่อยู่หน้าเว็บ (ฝั่งเกษตรกร)**: `/health/applications/<id>`

**ควรเห็นอะไร (ความจริงวันนี้)**
- ป้ายข้อความคงที่ **"รอนัดหมายลงพื้นที่ / เจ้าหน้าที่กำลังประสานวันนัดหมายประเมินหน้างาน"** — **ไม่มีวันที่
  ไม่มีเวลา ไม่มีชื่อผู้ตรวจ ไม่มีลิงก์ประชุม/ที่อยู่ ให้ดูในแอปเลย**

**จุดที่ยังไม่เปิด (สำคัญ — อย่าสัญญาเกินจริงตอนสาธิต)**
- ระบบหลังบ้านมีข้อมูลวันนัด/ผู้ตรวจ/ช่องทาง (ออนไลน์หรือลงพื้นที่) พร้อมอยู่แล้ว **แต่หน้าเว็บฝั่งเกษตรกร
  ยังไม่ดึงมาแสดงเลยสักหน้า** — เกษตรกรจะทราบวันนัดจาก**โทรศัพท์/ข้อความจากเจ้าหน้าที่ประสานงานเท่านั้น**
  ไม่ใช่ผ่านแอป (พบจาก code audit, เสนอเป็น finding ให้ทีมพัฒนา — ยังไม่ได้แก้)
- ฝั่งเจ้าหน้าที่ (Scheduler) ที่กำหนดวันนัด: `/provider/coordinator`, `/provider/calendar` — คนละหน้ากับที่
  เกษตรกรเข้าถึงได้ (นอกสโคปคู่มือฉบับนี้)

[ภาพหน้านี้เป็น dynamic route — **ต้องถ่ายเพิ่มด้วยมือ** จากคำขอที่อยู่ในสถานะรอนัดตรวจจริง]

- ข้อความ "พบข้อบกพร่องจากการลงพื้นที่ กรุณาส่งหลักฐานการแก้ไข" + ปุ่ม "ส่งหลักฐาน CAR"

**กดอะไร**
- แนบหลักฐานแก้ไข → ส่ง → เข้าสู่กระบวนการตรวจซ้ำ (ใช้ endpoint เดียวกับการยื่นคำขอ/แก้ไขเอกสาร)

**จุดที่ยังไม่เปิด**
- ไม่มี — ถ้าไม่มี CAR ระบบข้ามขั้นนี้ไปที่ "ใบรับรอง" ต่อได้เลย

[ภาพหน้านี้เป็น dynamic route — **ต้องถ่ายเพิ่มด้วยมือ** จากคำขอที่อยู่ในสถานะ CAR จริง — ถ้าไม่มีเคสทดสอบ
สถานะนี้บน staging ให้ข้ามภาพคู่นี้ไปก่อนและระบุใน manifest ว่า "ไม่มีเคสให้ถ่าย"]

## 8. ใบรับรอง + สแกน QR

**ที่อยู่หน้าเว็บ**: `/health/certificates` (รายการใบรับรอง) → `/health/certificates/<id>` (รายละเอียด +
ปุ่มดาวน์โหลด PDF) → `/verify/<เลขใบรับรอง>` (หน้าสาธารณะที่เห็นเมื่อสแกน QR)

**ควรเห็นอะไร**
- การ์ดใบรับรองพร้อมเลขที่ใบรับรอง, พื้นที่/ฟาร์ม, ชนิดพืช, วันออก/วันหมดอายุ, QR code
- หน้าดาวน์โหลด PDF (มี QR ฝังอยู่ในไฟล์)
- เมื่อสแกน QR (หรือเปิดลิงก์ `/verify/<เลขใบรับรอง>` ตรงๆ): หน้าสาธารณะแสดงสถานะใบรับรอง +
  พื้นที่/ชนิดพืช/วันออก-วันหมดอายุ **ไม่มีข้อมูลส่วนตัวของเกษตรกร** — ใครก็เปิดดูได้โดยไม่ต้องล็อกอิน

**จุดที่ยังไม่เปิด**
- ช่อง "ผลตรวจล่าสุด/ชื่อผู้ตรวจ" บนการ์ดใบรับรองที่หน้ารายการ (`/health/certificates`) **จะไม่แสดงข้อมูล
  ทุกกรณี** แม้ในระบบมีข้อมูลผลตรวจจริง — เป็นช่องว่างระหว่าง API สองตัวที่ยังไม่เชื่อมกัน (ไม่กระทบความถูก
  ต้องของใบรับรองเอง แค่ช่องนี้ว่างเฉยๆ)

[รูปที่จะแทรก: `evidence/staging-walkthrough/screenshots/farmer/NNN-health-certificates-mobile.png`]
[หน้ารายละเอียดใบรับรอง (`/health/certificates/<id>`) และหน้าผลสแกน QR (`/verify/<เลขใบรับรอง>`) เป็น
**dynamic route ทั้งคู่** — คิทถ่ายอัตโนมัติไม่ครอบคลุม **ต้อง operator ถ่ายเพิ่มด้วยมือ** จากใบรับรองทดสอบ
จริง 1 ใบ (แนะนำ: สแกนด้วยมือถือจริงแล้วแคปหน้าจอ เพื่อให้เห็นบริบทกล้อง/แอปสแกนด้วย ไม่ใช่แค่ URL)]

## ภาคผนวก — ข้อจำกัดของคู่มือฉบับนี้ (ต้องแก้ก่อนเผยแพร่จริง)

1. หน้า **dynamic route** ทั้งหมด (รายละเอียดคำขอ/ใบรับรอง/หน้าผลสแกน QR ฯลฯ) ยังไม่มีภาพ — ต้อง
   operator ถ่ายเพิ่มด้วยมือจากเคสทดสอบจริง แล้วแทนที่ช่อง `[ต้องถ่ายเพิ่มด้วยมือ]` ด้วยรูปจริง
2. ทุกภาพที่มีป้าย `[รูปที่จะแทรก: ...]` ยังเป็น **placeholder** — ต้องรัน
   `scripts/ops/run-walkthrough.sh` (หรือ workflow `staging-walkthrough.yml` เมื่อ Actions กลับมาใช้ได้)
   บน staging จริงก่อน แล้วนำไฟล์จาก `evidence/staging-walkthrough/screenshots/` มาแทน — ห้ามใช้ภาพจาก
   environment อื่น (local/mock) แทนภาพ staging
3. เนื้อหาขั้นตอน "จ่ายเงิน" ทั้งสองรอบต้องอัปเดตทันทีที่ L-090 (เปิดใช้ Stripe checkout จริง) ถูกแก้ — ห้าม
   ปล่อยให้คู่มือพูดว่า "จ่ายออนไลน์ได้" ก่อนของจริงเปิด
4. เนื้อหาขั้นตอน "นัดตรวจ" ต้องอัปเดตทันทีที่ L-091 (แสดงวันนัด/ผู้ตรวจในแอปฝั่งเกษตรกร) ถูกแก้
5. เอกสารนี้ยังไม่ผ่านการตรวจสอบภาษา/ศัพท์กับสกิล `thai-ui-copy` — ควรตรวจก่อนเผยแพร่ภายนอกหน่วยงาน
