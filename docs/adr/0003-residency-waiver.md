# ADR 0003: ยกเว้นกฎ "ข้อมูลไม่ออกนอกประเทศไทย" ชั่วคราว

สถานะ: ยอมรับชั่วคราว · วันที่: 2026-09-08 · ผู้ตัดสิน: operator ("กฎข้อนี้ยกเว้นก่อน")

## บริบท

ข้อกำหนดเดิมของแพลตฟอร์มคือข้อมูลส่วนบุคคลของผู้ขอรับรอง (เลขบัตร ที่อยู่ พิกัดแปลง) ต้องไม่ออกนอกประเทศไทย ในเฟส demo/staging operator ยกเว้นกฎนี้เพื่อความเร็ว โดยยอมรับบริการต่างประเทศดังนี้

| บริการ | ที่ตั้ง | ข้อมูลที่ไป | เหตุผลที่ยอมรับ |
|---|---|---|---|
| Supabase (Postgres + Storage) | Singapore | ฐานข้อมูลและไฟล์ทั้งหมด | มีอยู่แล้ว ทีมคุ้น เร็ว |
| Stripe | สหรัฐฯ | ชื่อผู้ซื้อ อีเมล ยอดเงิน วิธีชำระ (ไม่มีเลขบัตรประชาชน) | operator ตัดสินใช้เป็นช่องทางชำระเงิน |
| GitHub (repo + Actions) | สหรัฐฯ | โค้ดเท่านั้น ไม่มีข้อมูลผู้ใช้ | |
| Cloudflare | ทั่วโลก | traffic ผ่าน proxy | หน้าบ้านของ demo/staging |

## ข้อผูกพันที่ยังคงอยู่แม้ยกเว้น

- ทุกบริการภายนอกอยู่หลัง adapter ที่สลับได้ (`PaymentGateway`, storage adapter, DB connection string) ไม่มี type ของ vendor รั่วเข้า schema หรือเอกสาร
- ไม่มี runtime call ออกนอกระบบที่ไม่จำเป็น (ฟอนต์ self-host ไม่มี analytics ต่างประเทศ ไม่มี CDN สำหรับ asset)
- PDPA ยังเข้มเต็มตาม ADR 0001 ข้อ 8 การยกเว้นนี้เป็นเรื่องที่ตั้งของ server ไม่ใช่เรื่องสิทธิ์การเข้าถึง

## รายการที่ต้องทบทวนก่อนขึ้นเครื่องจริงของกระทรวง

1. ย้าย Postgres และ object storage เข้าไทย (AWS ap-southeast-7 กรุงเทพฯ หรือ GDCC) ผ่านการเปลี่ยน connection string และ storage adapter
2. สลับ `StripeGateway` เป็นผู้ให้บริการไทย (ธนาคาร/gateway ที่รองรับ PromptPay และ webhook) โดยไม่แตะ schema ใบเสนอราคา/ใบเสร็จ
3. ยืนยันขอบเขตข้อมูลบนหน้าสแกน T&T สาธารณะ (มติ 2026-09-05 เปิดชื่อฟาร์ม ที่อยู่ติดต่อ และ COA เป็นการผ่อนสำหรับ demo)
4. ทบทวน CI ที่รันบน GitHub Actions ว่ามีข้อมูลจริงหลุดเข้า fixture หรือ log หรือไม่
5. บันทึกผลการทบทวนเป็น ADR ใหม่ที่แทนที่ฉบับนี้
