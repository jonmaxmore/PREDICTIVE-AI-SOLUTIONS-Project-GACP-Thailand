# ADR 0001: หลักการผูกมัดของระบบ

สถานะ: ยอมรับ · วันที่: 2026-09-08 · ผู้ตัดสิน: operator

## บริบท

ระบบรุ่นที่ 1 พังจากการต่อเติมโดยไม่มีหลักกลาง (ดู [lessons-from-v1.md](../lessons-from-v1.md)) รุ่นที่ 2 จึงเขียนหลักที่เปลี่ยนไม่ได้ไว้ก่อนเขียนโค้ดบรรทัดแรก ทุก PR ต้องอ้างได้ว่าไม่ขัดข้อใดข้อหนึ่งต่อไปนี้

## หลักการ

1. ยื่นตามกรมเป๊ะ: ชุดเอกสารบังคับ = แบบกัญชา กทล.1 ส่วนที่ ๓ + checklist เจ้าหน้าที่ท้ายแบบ สิ่งที่เกินแบบต้องมี ruling เป็นลายลักษณ์อักษร
2. กัญชาก่อน: รองรับหลายพืชตั้งแต่ต้น (`plants` + ชุดกฎต่อพืช) แต่ไม่ reuse field ของกัญชาให้พืชอื่น UI แสดงเฉพาะพืชที่มีชุดกฎมีผล
3. กฎเป็นข้อมูล: requirement rules, fee schedules, checklist ตรวจแปลง, วันทำการ อยู่ในตารางที่มีวันมีผลและ append-only ค่าคงที่ทางธุรกิจในโค้ดถือเป็นข้อบกพร่อง
4. ไม่มีฟีเจอร์มอบอำนาจการยื่น หนังสือมอบอำนาจ + สำเนาบัตรผู้มอบเป็นเอกสารแนบตามกรณี ชื่อ `Site` กับชื่อ `Applicant` ผูกกันหนึ่งต่อหนึ่งและตรงกันทุกเอกสารเพื่อตรวจสอบย้อนหลัง
5. Auth production = ThaID + หมอพร้อม เท่านั้น local login เฉพาะ development (build ล้มถ้าเปิดใน production)
6. การแจ้งเตือนในระบบเท่านั้น ไม่มี email/SMS vendor
7. กฎถิ่นที่อยู่ของข้อมูลถูกยกเว้นชั่วคราว (ดู ADR 0003) แต่ทุก dependency ภายนอกต้องอยู่หลัง adapter ที่สลับได้
8. PDPA เข้ม: bucket private ทั้งหมด, signed URL อายุสั้น, ดูเอกสารผ่าน viewer ในหน้า, บันทึกทุกการเปิดดูของเจ้าหน้าที่ (ม.39) และแจ้งบนหน้าจอ (ม.37), เลขบัตรประชาชนไม่เก็บแบบอ่านได้ ไม่ลง log ไม่พิมพ์บนเอกสารเงิน, ตรวจเนื้อไฟล์จริง, เมทริกซ์ลบ/ปิดบัง/เก็บตาม [pdpa-retention.md](../pdpa-retention.md), พิกัด GPS ไม่เผยแพร่
9. ตั้งชื่อให้ถูกและไม่ใช้ชื่อเดิม ([glossary.md](../glossary.md) บังคับด้วย lint)
10. `Applicant` (นิติฐานะ 3 แบบ) ≠ `CertificationBody` (กรม)
11. ใบรับรองออกได้เมื่อมีหลักฐานการตรวจ ณ แปลงจริงเท่านั้น (ISO/IEC 17065 §7.4) และเซ็นดิจิทัลตรวจสอบย้อนได้
12. เส้นงานเส้นตรงและวิ่งอัตโนมัติจนถึงออกใบรับรอง: `ApplicationStatus` ชุดเดียว เปลี่ยนผ่าน `ApplicationWorkflow.transition()` เท่านั้น ทุก transition มีแถวประวัติ เงินแตะเส้นงานสองจุด (ชำระงวดที่ 1 → `SUBMITTED`, ชำระงวดที่ 2 → `AWAITING_INSPECTION`) ใบเสนอราคาทั้งสองงวดออกอัตโนมัติ
13. เงินก้อนเดียวหน้าบ้าน: ค่าธรรมเนียม + ค่าบริการ = ยอดรวมก่อนภาษี บวก VAT 7% เต็มทั้งก้อน = ยอดรวมสุทธิ คูณตามจำนวนรูปแบบการปลูก ราคาล็อก ณ วันยื่น บริษัทออกใบเสนอราคาและใบเสร็จรายเดียว ใครจ่ายใครเบื้องหลังไม่อยู่ในระบบ `FINANCE_OFFICER` ดูแค่ยอด
14. ข้อความไทยตาม glossary §7

## ผลที่ตามมา

- code review ข้อแรกคือ "ชื่อนี้อยู่ใน glossary ไหม" และ "ค่าคงที่นี้ควรเป็นข้อมูลไหม"
- ไม่มี feature flag ค้าง ไม่มีของที่ merge แล้วแต่ไม่เปิดใช้ (บทเรียน RLS "capable-not-live" ของ v1)
- CI เขียวเป็นเงื่อนไข merge ตั้งแต่ commit แรก
